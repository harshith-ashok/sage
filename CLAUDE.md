# SAGE — Sovereign Agentic (Grounded) Engine — Master Plan

Self-hosted, air-gapped AI workbench for confidential industrial/government work. **No component makes a network call after initial model download — ever.** If you're about to add a dependency or API call that reaches the internet at runtime, stop and flag it instead of adding it silently.

## Session discipline — read this before doing anything

This file drives many separate Claude Code sessions across a hackathon build. To avoid burning context/credit:

- **Work on exactly one unchecked phase per session.** Find the first `- [ ]` phase below, do only that phase's tasks, check them off, then **stop and summarize** — don't cascade into the next phase automatically. The user will say "continue" or name the next phase explicitly.
- **Don't view whole files/repos speculatively.** When porting from `insurance_claim_agent/` or `hi/`, grep or view the specific file/function you're adapting — not the full repo tree. use the CLAUDE.md (and/or) README.md files inside each repo as source of information
- **Prefer small, targeted edits over rewrites.** Use `str_replace` for a few changed lines, not a full-file rewrite, unless the phase genuinely requires a new file.
- **Don't re-read this file's already-completed phases in depth** — the checkboxes are the state; trust them.
- **Don't regenerate `PROJECT_PLAN.md` or `SAGE_Overview.md`** — they're reference docs with the full rationale for each phase. Consult them only if a phase's one-line summary here isn't enough to proceed.
- **No speculative scaffolding.** Build what the current phase asks for, not what a future phase might need.

      — **"Still not properly streaming, only shows the full output after" — root-caused as a frontend perf bug, not a backend one.** Verified the backend genuinely streams token-by-token at both the Python level (`graph.stream(stream_mode=["updates","messages"])`, real inter-chunk time gaps) and the raw HTTP/SSE level (a plain `urllib` client against `/agent/chat/{id}/stream` showed the same real-time spread) — so the transport was never the problem. Root cause was in `ConsoleView.vue`'s `scrollToBottom()`: it was called on _every_ `token`/`thinking` SSE event (dozens per second) and did `await nextTick()` then `scrollTo({behavior: "smooth"})` uncoalesced — each call queued a fresh smooth-scroll animation before the last one finished, starving the compositor of paint time for the actual text updates, so nothing visibly moved until the flood of scroll calls stopped and the whole response appeared to "jump in" at once. Fixed by coalescing to at most one scroll per animation frame (`requestAnimationFrame`, instant `"auto"` behavior while tokens are still arriving, `"smooth"` only for the one-off send/complete moments) and only auto-scrolling when already near the bottom (so it stops yanking the view back down if the user scrolled up mid-stream to reread something).
